# v0.3 第五至第九项执行记录

更新日期：2026-09-05。对应根目录 AGENTS.md 的第五至第九节。当前改动保留本地，尚未发布 GitHub。

## 五、复用与存储

- 已实现按内容保存独立快照、模块依赖校验和共享对象存储。
- 同一存档导出不同国家数量复用世界基础模块；补充完整人口仅计算缺少的部分。
- 解析版本与报告版本分开；仅修改展示逻辑不要求重新解析基础模块。
- 跨年份只复用依赖完全相同的模块，不按国家名称继承旧值。
- 本次相邻年份实测只命中战争、战斗两个模块。该结果不证明大部分历史数据都能复用。
- 静态文化及名称环境参与复用校验；没有另外建立全游戏商品、建筑定义数据库，不将其列为已完成能力。

## 六、性能与技术栈

- Python 主程序、SQLite 持久化、现有社区解码工具继续使用。
- 修复条目循环不断复制文件剩余部分的问题，使用偏移定位；结构扫描跳过普通文本、字符串和注释。
- 建立顶层数据块索引，保存各模块耗时、缓存命中和跨快照命中记录。
- SQLite 连接显式关闭，消除 Windows 下阻止缓存目录发布的文件占用问题。
- JSONL 兼容表接口按需查询 SQLite，不再默认创建一整份 JSONL 镜像。
- 本轮未引入 Rust。现有 Python 路径已获得实测收益，未来按剩余瓶颈决定是否加入局部加速。

历史存档对照测试均为完整人口、5国报告。基础提取覆盖所有国家，报告按选择范围筛选。

| 存档内部身份 | 原流程 | 优化后一次测量 | 原有表格内容比较 |
|---|---:|---:|---|
| 朝鲜 1837-07-31 | 69.96秒 | 11.86秒 | 一致 |
| 中国 1894-02-12 | 125.51秒 | 27.46秒 | 一致 |
| 中国 1889-01-16 | 155.56秒 | 31.53秒 | 一致 |

以上优化后测量包含新转换缓存建立开销；属于本机单次样本，不是多次统计均值或对所有存档的保证。

端到端测试记录：

| 使用情形 | 实测耗时 | 说明 |
|---|---:|---|

| 同存档同范围再次读取 | 0.379秒 | 完整校验后复用 |
| 同存档从5国改导30国 | 2.562秒 | 复用20个模块 |

实际使用预期：此批样本首次处理约10至35秒，同视图缓存约1秒内，换范围或补充模块通常数秒。更复杂的存档、磁盘竞争或不同解码格式可能超出此范围。首次解析与缓存耗时须分别报告。

## 七、历史资料

- 保留原有国家、经济、社会、市场、条约、附属关系与战争相关表格及MD章节。
- 增加显式选择两个数据包的历史对照，展示经济人口、地区归属、附属关系、法律、市场成员、条约条款、政治运动与战争记录差异。
- 增加显式选择三个以上数据包的战役时间线，按游戏日期排列相邻快照变化。
- 历史读取使用流式数据库遍历，取消固定两百万行上限。
- 缺表时标注无法比较，不能把未导出的内容写成消失；比较差异不等于证明因果。
- 不自动混合不同游戏局；单个存档已经丢弃的历史仍无法恢复。

## 八、终端与输出

- 主菜单：导出最新MD、选择存档批量导出、资料库与设置。
- 实际进度单行更新，处理中文显示宽度；没有井号进度条或虚构剩余时间。
- 默认MD直接放桌面资料库第一级，转换、数据库和测试文件留在F盘。
- 完成后显示实际耗时和位置，正常操作打开文件夹而非报告。
- 批量任务展示成功、失败数量，并列出失败存档。
- 资料库与设置中加入 `v0.3 验收检查`，可生成可复查的 Markdown 验收报告。
