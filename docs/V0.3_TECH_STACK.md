# v0.3 技术栈与读取策略

v0.3 的目标不是继续堆 Python 正则，而是把项目变成“存档数据平台”：

```text
.v3 存档
  -> 快速索引
  -> 可插拔高速解码 / Python 回退
  -> 世界模块快照
  -> 标准数据包
  -> Markdown / SQLite / API
```

## 主技术栈

| 层 | 技术 | 作用 |
|---|---|---|
| 终端入口 | Python | 菜单、批量选择、报告流程 |
| 快速索引 | Python + 持久化 JSON | 只读文件头和文件指纹，快速显示国家、日期、版本 |
| 高速后端 | Garibaldi native extractor / Rakaly melter / Rust 顶层块扫描器 | 处理二进制、压缩或大文本扫描 |
| 回退后端 | Python text/zip reader | 外部工具不可用时保证还能导出 |
| 世界模块快照 | SQLite + 内容寻址对象 | 复用国家、地区、人口、外交、战争等基础模块 |
| 标准数据包 | SQLite | 后续 API、报告和聊天读取都读缓存 |
| 文档输出 | Markdown | 用户最终主要阅读格式 |
| 本地接口 | 标准库 HTTP API | 不强依赖 Web 框架，双击环境更稳 |
| 可选 Rust | `rust/vic3_parser_rs` | 已提供顶层块 offset 扫描器骨架，未编译时自动走 Python |

## 速度策略

1. 存档列表不深扫，只使用 `data_cache/save_catalog.json` 中的预览缓存。
2. 快速指纹只用于筛候选，正式复用使用完整 SHA-256 与输出文件哈希。
3. 重复构建同一存档时直接复用标准数据包，不再重新解析 `.v3`。
4. 同内容存档通过 `data_cache/content_index.json` 复用同一个已生成视图，即使文件名或路径不同。
5. 二进制/未知存档优先尝试 Garibaldi 原生提取器，并把展开文本保存在 `data_cache/melted/` 或 `data_cache/native_extract/`。
6. SQLite 负责高频查询；JSONL 兼容接口按需从 SQLite 读取，不默认生成镜像文件。
7. Rust 顶层块扫描器位于 `rust/vic3_parser_rs`；编译后 `api_server.py status` 会显示可用。
8. 未来若继续 Rust 化，优先迁移人口流式提取和结构扫描，不重写终端、报告和 API 编排层。

## 当前后端顺序

```text
text/zip 可直接读 -> Python 直接读
binary/unknown -> Garibaldi native extractor -> Garibaldi/Rakaly melter -> 报错提示安装工具
optional -> Rust 顶层块扫描器 -> Python 模块提取与报告
```

## 诊断命令

```powershell
python api_server.py status
python api_server.py build --save latest
python api_server.py serve
```

健康检查：

```text
http://127.0.0.1:8765/api/health
```

JSONL 表读取：

```text
http://127.0.0.1:8765/api/jsonl/table/major_countries?dataset=latest&limit=100
```

Rust 扫描器：

```powershell
cd rust\vic3_parser_rs
cargo build --release
python ..\..\api_server.py status
```
